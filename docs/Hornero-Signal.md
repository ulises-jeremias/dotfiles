# Hornero Signal on this workstation

Hornero Signal is the visual language and experience layer shipped by the
HorneroOS packages (config 0.4.0, shell 1.3.0, horneroctl 0.2.0_preview46).
This source does not implement any of it. It keeps only personal choices and
makes sure the host has what Signal expects.

## What the packages own

| Area                                                                             | Owner                                                             | Notes                                                                         |
|----------------------------------------------------------------------------------|-------------------------------------------------------------------|-------------------------------------------------------------------------------|
| Themes `hornero-signal-night`, `-day`, `-contrast`                               | HorneroOS/config                                                  | Schema v2: a fixed role set plus a 16-colour terminal ramp, no Material roles |
| Hornero Chromatic (wallpaper or seed palettes, gated for contrast)               | config templates, shell engine, `horneroctl appearance chromatic` | Theme id `hornero-chromatic`; state under the XDG Hornero paths               |
| Layouts and presets (Cockpit is the factory layout)                              | HorneroOS/shell                                                   | Switched in Control Center or with `horneroctl shell preset`                  |
| Experience modes (Focus, Everyday, Signal, Gaming, Studio)                       | HorneroOS/shell, `horneroctl mode`                                | `horneroctl mode set signal`; `mode reset --yes` restores factory             |
| PluginKit 3 and the desktop deck                                                 | shell and HorneroOS/plugins                                       | Extensions are installed through horneroctl or Control Center                 |
| Hyprland Lua modules (including `layers{}` and `hl.dsp.group.lock()` migrations) | HorneroOS/config                                                  | Factory modules are never copied here                                         |
| Type (IBM Plex Sans, Mono)                                                       | packages depend on `ttf-ibm-plex`                                 | Material Symbols and Rubik are retired                                        |

## What this source keeps

- `home/dot_config/hypr/hyprland.lua.d/monitors-user.lua` and
  `keybindings-user.lua`: the packaged user extension points, loaded after the
  factory modules. `horneroctl hardware keyboard rebind` also writes the
  keybinding file. Window rules go through `horneroctl hypr windows rules`
  into `window-rules-user.lua`, which this source does not track.
- `fontconfig/fonts.conf` and `fastfetch/*`: kept byte-identical to the
  packaged copies so the user-level files fontconfig and fastfetch read first
  agree with Signal. Re-sync them when HorneroOS/config changes them (see the
  [migration ledger](Chezmoi-Migration-Ledger.md)).
- `gtk-3.0/settings.ini`, wallpapers, btop/Cava selecting `Hornero Dynamic`
  (regenerated by every theme apply).

## Personal preferences: where they live

Everything visible is a setting, not a patch. Use the product mechanism and
never edit factory files or state:

| Preference                                          | Mechanism                                                                                                        |
|-----------------------------------------------------|------------------------------------------------------------------------------------------------------------------|
| Theme, contrast, wallpaper-derived palette          | Control Center Appearance, or `horneroctl appearance theme set <id>` and `horneroctl appearance chromatic apply` |
| Layout, bar thickness, density, radii, glow, motion | Control Center; persisted in `~/.config/hornero/shell.json`                                                      |
| Experience mode and per-mode overrides              | Control Center Experience, or `horneroctl mode set <mode>`                                                       |
| Extra Chromatic app targets                         | Manifests in `~/.config/hornero/chromatic/templates.d/`                                                          |
| Keybinds, monitors, window rules                    | The `*-user.lua` files above                                                                                     |

`~/.config/hornero/shell.json` and `~/.local/state/hornero` are runtime state
written by the Shell. They are deliberately not tracked or templated by
chezmoi: a tracked copy would be overwritten on every apply and fight the
Shell's own migrations.

## Upgrade notes

1. Packages first: the bootstrap script prints an advisory when config, shell
   or horneroctl are below the Signal releases; it does not fail. The hard
   floors move to the Signal versions once they are published to the AUR.
2. Pre-Signal shells keep Material Symbols and Rubik installed; after the
   upgrade they can be removed with
   `sudo pacman -Rns ttf-material-symbols-variable-git ttf-rubik-vf`.
3. An existing `~/.config/qt6ct/qt6ct.conf` is the user's and is not
   replaced. Applying a Hornero theme repoints its palette; to take the new
   factory defaults, move it aside and re-run the apply.
4. Retired theme ids (`hornero-light`, `hornero-dark`) are migrated by the
   shell and horneroctl; nothing here references them.
